# Agent notes

This is Stevey's fork of ppixiv, branch `stevey`. It folds the ppixiv-zh features into the source and adds a redesigned interface. `origin` is upstream ppixiv, so never push there. The fork's own repo is the remote `fork` (public, `github.com/Stevey233/ppixiv-next`); the script's `@updateURL` reads `dist/ppixiv-next.user.js` from its `stevey` branch, so a push there updates every install. Push only when Stevey asks.

## Language

- Code, code comments and commit messages are in English.
- Repo docs for Stevey (the top of `readme.md`, `docs/design.md`) are in Simplified Chinese.
- UI strings are Chinese. Strings written in this fork are Chinese in the source. Upstream's English strings are translated at runtime by `web/vview/zh/` (`dict.js` and `i18n.js`), so add missing upstream strings to `dict.js` instead of editing upstream templates.

## Where things are

- `web/vview/next/`: the new widgets (navigation rail, filter bar, theme, one-click bookmark, thumbnail page turning, follow button, user rows, the "since last time" marker, the artist's works strip, the shortcuts page).
- `web/resources/css/_next.scss`: all styles of the redesign. It's imported last from `main.scss` and overrides upstream rules. Keep upstream's own SCSS unchanged where possible, so upstream merges stay easy.
- `web/vview/misc/result-filters.js`, `seen-works.js`, `download-names.js`, `hd-thumbnails.js`, `preload.js`: the features from ppixiv-zh. `muted-works.js` and `downloaded-works.js` (the record behind the downloaded marker) are the fork's own.
- `web/vview/sites/pixiv/data-sources/history.js`: the 最近看过 list, built on the seen-works record.
- `web/vview/sites/pixiv/data-sources/from-bookmarks.js` and `web/vview/misc/seed-feed.js`: the 收藏相关 list (related works of the newest bookmarks), its request spacing and its IndexedDB cache. Its request budget is in `docs/design.md`; don't add requests to it without Stevey's yes.
- `web/vview/sites/pixiv/data-sources/tag-feed.js`, `web/vview/misc/tag-feed.js` and `web/vview/next/tag-sections.js`: the 常看标签 list (Pixiv's home page recommendations per tag, one request kept 10 minutes) and its section headers, which `ThumbnailGrid` in `search-view.js` places between rows. `web/vview/next/recommend-options.js` is the option row of all three recommendation lists.
- `web/vview/next/tag-refine.js`, `related-tags-row.js` and `web/vview/misc/pixiv-links.js`: adding or excluding a tag in the current search, the related tags line on tag search, and pasted Pixiv links in the search box.
- `web/vview/sites/gelbooru/`: the same interface on gelbooru.com. `site-gelbooru.js` is the site (caps, hooks, rail), `api.js` owns every request (the API key, request spacing, decoding Gelbooru's HTML-escaped text), `query.js` parses and builds the `tags` query that is a list's whole state (tags plus conditions), `media.js` maps a post to media info, `conditions-ui.js` and `search-defaults.js` are the condition menus and the default conditions, `favorites.js` and `store.js` the local favorites set and its IndexedDB, `popular.js` 热门, `tag-categories.js`, `tag-library.js`, `tag-names.js` and `tag-library-dialog.js` the tag categories, the tag pack, Chinese names and the 标签库 screen, `data-sources/` the lists (`gb-posts`, `gb-post`, `gb-history`). Styles are `web/resources/css/_gelbooru*.scss`, imported after `_next.scss`. The plan and what the real site answers are in `.work/gelbooru/DESIGN.md` and `API.md`.
- The tag pack `data/gelbooru-tags.<version>.tsv.gz` (with `data/gelbooru-tags.json` and `data/README.md`) is built by `tools/build-gelbooru-tags.py`; `PACK_VERSION` in `tag-library.js` must match the manifest. `test/tag-library.mjs` tests the library and `test/gelbooru-query.mjs` the query parser.
- Pixiv-only features are gated by `ppixiv.site.caps` (and `body.no-<cap>` classes in CSS) or by an optional hook on `ppixiv.site` that falls back to the Pixiv path, never by hostname checks. Only `app-startup.js` and `startup/bootstrap.js` look at the hostname. Pixiv behavior must not change when a hook is added.
- `docs/design.md`: the design and the reason for every behavior change. Update it when behavior changes.

## Build and check

- Build with `./tools/build.sh`. Commit `dist/ppixiv-next.user.js` at milestones, since that's the file Stevey installs.
- `.work/harness/` has a Playwright harness that serves fixture Pixiv responses, for screenshots without a login: `cd .work/harness && STEPS=shots.mjs PREFIX=x- node harness.mjs`. Other step files: `mobile.mjs`, `settings.mjs`, `probe.mjs`. Step files that print `ok` or `FAIL` per check and add their own fixture routes: `logic-*.mjs` (paging, seen works, bookmark, follow and download requests), `filters-logic.mjs`, `quickbm-logic.mjs`, `muted-logic.mjs`, `rwheel-logic.mjs`, `changelog-*.mjs`, and one `r2-<feature>-logic.mjs` per feature added on 2026-11-13. A step's header names the harness file it needs (`harness.mjs`, `visual-harness.mjs` or `r2-userrows-harness.mjs`). The features added on 2026-11-14 have `r3-<feature>-logic.mjs`, and `r3-break-logic-*.mjs` exercise how those features meet. `r4-fail-*-logic.mjs` (run with `perf-harness.mjs`) answer a list page or a work's info with a 429, 403, HTML error page or dropped connection and check the list and the viewer recover; `r4-fail-persist.mjs` counts requests while a page keeps failing (70 s). `perf-session.mjs` (list switching and work flipping, heap and listeners after GC) and `perf-grow-mem.mjs` (DOM nodes, images and process RSS as a list grows) measure long sessions. `.work/harness/r3-run-all.sh <built user.js> [repo root] ["step names"]` runs every `r2-` and `r3-` logic step with the right harness, then `test/run.sh`, and prints the FAIL lines; run it after a merge and before a release, and expect 0 FAIL. The fixture's 推荐作品 answers every request with the same 24 works in fixed bookmark states, and the list keeps asking (1.5 s apart) until its used-up stop about 5 s after it opens, so a step that bookmarks or reads viewer tags on 推荐作品 waits 7 s first, or a later fixture response puts the old state back. Fixture responses are built in the step; never let a request through to the real site (`route.fetch()`, `route.continue()`). Every harness starts Chromium with `--host-resolver-rules` mapping `gelbooru.com`, `pixiv.net` and `pximg.net` (and their subdomains) to `~NOTFOUND`, because Playwright doesn't route the target of a fulfilled redirect: a 302 fixture would otherwise reach the real site. Test redirect outcomes by stubbing `window.realFetch` in the page. `visual-harness.mjs` with `visual-*.mjs` screenshots every screen and state, and `perf-harness.mjs` with `perf-*.mjs` measures startup, list growth and scrolling; `.work/optimize-2026-11-12/perf.md` has the commands and the baseline numbers.
- `test/run.sh` runs the feature tests.
- `.work/harness/gel-harness.mjs` runs the build on a fixture gelbooru.com (logged in, every request answered by a fixture, any Pixiv request recorded): `cd .work/harness && STEPS=<step>.mjs node gel-harness.mjs <dist.user.js>` (the default is the repo's `dist/`). Step families: `gel-f-` foundation, `gel-a-` conditions and related tags, `gel-b-` viewer, tags and downloads, `gel-c-` lists, favorites and the rail, `gel-d-` tag library and Chinese names, `gel-r-` fixes from review and the live check. Run all of them and expect 0 FAIL: `for s in gel-*-logic.mjs; do echo "$s $(STEPS=$s node gel-harness.mjs ../../dist/ppixiv-next.user.js 2>&1 | grep -c FAIL)"; done`. `gel-a-settings-pixiv.mjs` and `SITE=pixiv` with `gel-c-changelog-logic.mjs` run on `harness.mjs`. `gel-f-viewer-logic.mjs`'s "viewer: the video plays" can fail under load; run it alone before calling it a defect. After a change to shared code, also run `r3-run-all.sh` for Pixiv.
- The build puts `.dirty` in `@version` when the tree has changes, and a modified `dist/` counts. Before the build you commit, commit the source and run `git checkout dist`.
- Check on the real pixiv.net before calling a UI change done. ppixiv needs a logged-in page. The T3 preview's Default profile is logged in and has no Tampermonkey: serve the build with `.work/live/serve.py dist/ppixiv-next.user.js 8899`, open `https://www.pixiv.net/robots.txt`, then run this in the page:

  ```js
  (async()=>{const t=await(await fetch('http://127.0.0.1:8899/b.js')).text();document.open();document.write('<!doctype html><html><head></head><body></body></html>');document.close();history.replaceState(null,'','/discovery#ppixiv');setTimeout(()=>(0,eval)(t),0)})()
  ```

  Load `http://127.0.0.1:8899/shim.js` the same way before the script, since a hidden tab stops timers. A hidden preview tab doesn't render: `preview_snapshot` times out, and a `preview_evaluate` that awaits a timer times out too, so click in one call and read the result in the next (`await null` is enough to let the translation observer run). For the same reason, `content-visibility: auto` rows skip hit testing and clicks miss. Click links from script (`a.click()`) or take a snapshot first. `ResizeObserver` and `IntersectionObserver` callbacks never fire in the hidden tab either, so scrolling loads nothing (call `dataSource.loadPage(n)` instead) and dropdowns stay where their first layout put them: a dropdown measured off the window's edge there is not a defect. ppixiv replaces `window.setTimeout` and `window.fetch`, so a probe sleeps with `window.realSetTimeout` and fetches with `window.realFetch`. Only browse. Never bookmark, like or follow on Stevey's account from a test. A click on a filled heart on a thumbnail removes that bookmark, so never click a heart, and check what a scripted click lands on before sending it.
- Check Gelbooru changes on the real gelbooru.com in the T3 preview; its Default profile is logged in there with Stevey's Gelbooru test account. Unlike the Pixiv account, tests may add and remove favorites on it; leave 收藏时同时点赞 off, since removing the favorite doesn't take the vote back. Open `https://gelbooru.com/robots.txt` and point the tag pack at the local server (settings are JSON in localStorage), since the default pack URL on raw.githubusercontent.com only has the pack once the commit is pushed:

  ```js
  localStorage['_ppixiv_gelbooru_tag_pack_url'] = JSON.stringify('http://127.0.0.1:8898/pack.tsv.gz')
  ```

  Then load `shim.js` and the script as in the Pixiv recipe, with `history.replaceState(null,'','/index.php?page=post&s=list&tags=…#ppixiv')` in place of `/discovery#ppixiv`. The same hidden-tab limits apply. Afterwards run `delete localStorage['_ppixiv_gelbooru_tag_pack_url']`.
